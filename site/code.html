Stage 2: verify and retry

✕ Gate not met

The standard model answers each of the 257 MBPP tasks. If its answer fails the one test a user can see, the error message goes back to the model for up to two more tries. Hidden tests decide whether the task is really solved.

Gain from retrying✕ Not met
+2.7 pts

50.2% on the first try, 52.9% after repair. The gate asked for +10 points at similar time; repair tripled the time per task (5.0 s to 15.1 s).

Repairs that workedLow
7 of 113

Only 9 retries made the visible test pass, and 7 of those passed the hidden tests. No retry broke an answer that already worked. This 1.5B model mostly cannot use an error message to fix its code.

The visible test is a useful but leaky judge. Anything that retries or searches on code while trusting it inherits that 10% error. Sudoku's rule check, by contrast, is exact.

Phase 2: try several, and learn from what works

Round 2 paused

Instead of repairing one answer, the model samples 8 answers per task and submits the first that passes the visible test. Then it is fine-tuned on its own solutions to separate training problems (MBPP train and validation, never the test set), keeping only answers that pass every test.

Sampling and checking works: +20.6 points over one answer, versus +2.7 from repair. Round 1 of self-training did not: none of the changes is significant, because 44% of its 972 verified solutions came from problems it already found easy. Round 2 trains only on the frontier (problems solved at most half the time) and is paused 9 of 139 problems into its first step.

How it was measured

    What this means

    The diffusion model is faster per token, but it writes longer answers and solves fewer tasks. On a laptop at batch size 1, it does not pay off yet. Both models also leave the GPU mostly idle, because Python overhead per step dominates.

    Stage 2 tested checking and retrying: it added 2.7 points for three times the time, because the model was never trained to use feedback. The next step is to train it on its own verified work: sample several answers, keep the ones that pass, and fine-tune on those. That is how the Sudoku and maze models learned to be reliable without more data.
